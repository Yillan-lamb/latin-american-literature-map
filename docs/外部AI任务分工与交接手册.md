# 拉丁美洲文学地图：外部 AI 任务分工与交接手册

版本：0.3.1

用途：将本文件与对应资料、任务模板一起交给其他 AI，即可直接开始基础工作

> 所有外部 AI 开工前必须完整阅读仓库根目录 `PROJECT_CHARTER.md`。该文件是用户锁定的最高项目总章程，任何外部 AI 均不得修改、移动、重命名或删除。

## 1. 这份手册解决什么问题

本项目把高重复、低判断风险、消耗大量上下文的资料处理交给其他 AI，把有限的 Codex 用量保留给知识模型、证据判断、关系审核、数据库整合和项目收口。

外部 AI 不是独立决定项目方向的研究者，而是领取标准任务包的 Worker。它的成果必须让一个没有参与对话的 Codex 能够理解、复核和继续处理。

## 2. 总体职责分配

| 工作 | 其他 AI | Codex | 用户 |
|---|---|---|---|
| 文件清单、格式和页数盘点 | 主做 | 抽检、编号 | 提供资料 |
| 版权页、目录和指定章节 OCR | 主做 | 设定范围、抽检 | 无需逐项审核 |
| Markdown 结构整理和页码锚定 | 主做 | 退回不合格结果 | 无需逐项审核 |
| 来源档案和书目信息初填 | 主做 | 分配正式来源 ID、解决冲突 | 无需逐项审核 |
| 作家名、作品名、地点等候选抽取 | 主做 | 规范化并确认 | 无需逐项审核 |
| 重复项、别名和译名候选检测 | 主做 | 决定是否合并 | 无需逐项审核 |
| 文学影响、主题和争议性关系 | 只提供候选和定位 | 主做判断与复核 | N2/N3 看代表性结果 |
| Schema、SQLite 和数据迁移 | 不做 | 主做 | N2 审核 |
| 作家卡、作品卡和策展文本 | 可提供事实素材 | 主写或最终审核 | N3 审核 |
| Git、GitHub、版本和公开边界 | 不做 | 主做 | N4 批准发布 |

## 3. 外部 AI 的统一硬规则

每次把任务交给外部 AI 时，都必须同时提供：

1. 一个唯一任务 ID；
2. 明确的输入文件；
3. 允许处理的页码、章节或字段；
4. 应生成的文件清单；
5. `PROJECT_CHARTER.md`；
6. 本手册和 `docs/阶段0_研究与数据规范.md`；
7. 对应的 `templates/external-ai/` 模板。

外部 AI 必须遵守：

- 只处理当前任务，不擅自扩展到其他文件、章节或研究问题；
- 不修改、移动、重命名或删除 `PROJECT_CHARTER.md`；
- 不修改原始文件，不改 `TASKS.md`，不写主数据库，不操作 GitHub；
- 不把用户资料上传到公开链接；
- 不用常识填补 OCR 缺字，不编造页码、出版信息或来源；
- 不把候选结论写成已确认事实；
- 每个事实或候选项保存来源 ID和页码/章节/电子位置；
- 无法确认的内容进入 `ISSUES.md`；
- 交付必须是完整文件包，不能只有聊天窗口中的总结；
- 完成后生成 `HANDOFF.md`，明确告诉 Codex 下一步该做什么。

## 4. 标准任务包结构

外部 AI 必须返回以下结构。没有某项成果时保留文件并写“本任务不适用”。

```text
<TASK-ID>_<任务主题>/
├── README.md
├── STATUS.md
├── MANIFEST.md
├── SOURCE_RECORD.md          # 来源建档任务
├── OCR.md                    # OCR 任务
├── ENTITY_CANDIDATES.csv     # 候选抽取任务
├── RELATION_CANDIDATES.csv   # 经任务卡允许时才生成
├── QA_REPORT.md
├── ISSUES.md
├── REVIEW.md                 # 独立 Reviewer 任务
└── HANDOFF.md
```

不要自行改名为“最终版”“整理结果2”“完整结果”等无法批量识别的名称。

## 5. 过程状态要求

外部 AI 至少在以下时间更新 `STATUS.md`：

1. 开始时：记录 Agent、模型、任务理解、输入和预计步骤；
2. 完成约一半时：记录已完成范围、发现的问题和剩余工作；
3. 结束时：状态必须写 `done`、`blocked` 或 `failed`；
4. 任何需要用户/Codex决定时：写 `needs_input: yes`，说明具体问题和可选方案。

对于无法持续写文件的平台，可以在结束时补写过程时间线，但不得省略中间发现的问题。

## 6. 可直接分配给其他 AI 的任务类型

### A. 文件接收与资料清单

适合：任何能读取文件名、PDF 元数据或截图的 AI。

输入：一批文件或文件目录。

执行步骤：

1. 逐个记录原文件名，不重命名原件；
2. 判断格式、文件大小、页数、是否有文字层和主要语言；
3. 初步识别题名、作者、译者和版本；
4. 标记重复文件、损坏文件、加密文件和疑似扫描件；
5. 建议后续处理为 L0/L1/L2/L3；
6. 标记可能含隐私、版权全文或其他敏感内容的文件。

必须交付：`SOURCE_MANIFEST.csv`、`QA_REPORT.md`、`ISSUES.md`、`HANDOFF.md`、`MANIFEST.md`。

禁止：阅读后自行做文学分析；给来源分配正式 `SRC-` 编号；公开上传文件。

验收：文件数量与输入一致；每个文件有处理建议；无法读取的文件明确列出。

### B. 单份来源建档

适合：OCR、文档阅读和书目整理能力较强的 AI。

输入：一个来源文件、任务 ID、Codex 分配的来源 ID。

执行步骤：

1. 定位封面、版权页、目录、参考文献和索引；
2. 抄录题名、作者/机构、译者、出版社、出版年、版次、ISBN/DOI；
3. 判断资料类型和语言；
4. 记录文件格式、页数、目录结构和引用定位方式；
5. 按规范提出来源等级建议；
6. 记录版权和使用限制；
7. 对每个不确定字段给出页面依据和问题说明。

必须交付：`SOURCE_RECORD.md`、必要的指定页 OCR、`QA_REPORT.md`、`ISSUES.md`、`HANDOFF.md`。

禁止：根据网名或文件名猜出版社、年份、ISBN；把来源等级建议写成最终结论。

### C. OCR 与 Markdown 结构整理

适合：带 OCR、视觉识别或文档解析能力的 AI。

输入：一个文件、明确页码/章节、OCR 层级。

执行步骤：

1. 先检查页码、栏数、脚注、表格和图片；
2. 只处理任务卡规定的范围；
3. 在每页起始处写 `<!-- page: N -->`；
4. 保留标题、段落、列表、脚注和表格结构；
5. 无法辨认写 `[无法辨认]`；
6. 对专名、数字、年份、作品名和引文进行重点核对；
7. 按开头、中部、结尾抽样，并记录准确率和错误类型；
8. 删除重复页眉页脚时在 QA 中说明。

必须交付：`OCR.md`、`QA_REPORT.md`、`ISSUES.md`、`STATUS.md`、`HANDOFF.md`、`MANIFEST.md`。

禁止：总结或润色原文；把不清楚的词按语义补全；超出任务范围做整书 OCR。

### D. OCR 独立质检

适合：没有参与原 OCR 的第二个 AI。

输入：原文件、OCR.md、原 Worker 的 QA 报告。

执行步骤：

1. 核对任务规定的抽样页；
2. 检查页码锚点、漏段、错序、脚注、表格和乱码；
3. 重点核对专名、年份、数字、作品名和短引文；
4. 判断错误是否影响研究使用；
5. 给出 `pass`、`revise` 或 `reject`；
6. 对每个问题写明 OCR 行号、原页码和建议。

必须交付：`REVIEW.md`、独立 `QA_REPORT.md`、`HANDOFF.md`。

禁止：只写“整体不错”；直接覆盖原 Worker 文件；自行降低准确率门槛。

### E. 候选实体和明确事实抽取

适合：能读结构化文本并输出 CSV 的 AI。

输入：已通过 QA 的 OCR、来源 ID、试行词表。

允许抽取：明确出现的作家、作品、地点、机构、文学运动、事件、主题词、出版信息和可直接从句子确认的基础关系。

执行步骤：

1. 每个候选使用暂存 ID；
2. 保存规范名称候选、原文名称和原文中的别名；
3. 保存来源 ID、页码/章节和短证据；
4. 标记置信度；
5. 同名不同人、译名冲突和指代不明进入问题清单；
6. 对影响、代表、回应等解释性关系只提出候选，不下最终结论。

必须交付：`ENTITY_CANDIDATES.csv`；任务卡允许时交付 `RELATION_CANDIDATES.csv`；以及 `QA_REPORT.md`、`ISSUES.md`、`HANDOFF.md`。

禁止：自行分配正式实体 ID；自行新建关系词；删除看似重复的候选；用训练知识补充 OCR 中没有的事实。

### F. 译名、别名和重复项候选核对

适合：表格处理、文本比对能力较强的 AI。

输入：候选实体表、来源记录和规范名称列。

执行步骤：

1. 归组拼写差异、重音差异、中文译名和原文名；
2. 标记“高度可能同一实体”“可能同一实体”“不可判断”；
3. 为每项给出来源依据和判断理由；
4. 单列同名异人风险；
5. 不执行删除或合并。

必须交付：候选对照表、`ISSUES.md`、`HANDOFF.md`。

禁止：无来源强行统一中文译名；仅凭字符串相似就认定同一实体。

### G. 书目与网络来源机械核对

适合：具备联网检索能力的 AI。

输入：待核对书目、允许访问的网站范围、来源 ID。

优先来源：出版社、图书馆、大学、DOI/Crossref 类权威目录、作家基金会。

执行步骤：

1. 核对题名、作者、出版年、出版社、ISBN/DOI；
2. 保存每个网页的标题、机构、URL 和访问日期；
3. 记录不同来源之间的冲突；
4. 不用普通电商页面覆盖权威书目；
5. 输出“已确认”“有冲突”“未找到”。

必须交付：书目核对表、URL 清单、`QA_REPORT.md`、`ISSUES.md`、`HANDOFF.md`。

禁止：使用搜索结果摘要代替打开页面；编造无法访问页面的内容；把普通网页作为文学解释唯一来源。

## 7. 保留给 Codex 的工作

以下工作不要交给基础 OCR/整理 AI：

- 未经用户明确授权不得修改 `PROJECT_CHARTER.md`；获得授权后也只能由 Codex 按章程变更程序执行；
- 修改关键决策和用户审核节点；
- 设计、冻结或迁移 Schema；
- 分配正式来源 ID 和正式实体 ID；
- 判断文学影响、运动归属、主题解释和来源冲突；
- 决定候选实体是否合并；
- 把暂存成果写入 SQLite 主数据库；
- 生成跨来源作家卡、作品卡、主题说明和策展路径；
- 运行 V1 覆盖、关系、引用和一致性审计；
- 更新 CHANGELOG、决策记录、README、Git 和 GitHub；
- 在 N1—N4 向用户提交节点审核包。

```text

允许范围：<页码、章节或字段>
禁止范围：不得修改 PROJECT_CHARTER.md、原件、主数据库、TASKS 或 GitHub；不得扩大范围、公开上传资料或猜测缺字和来源。

你必须先阅读：
1. PROJECT_CHARTER.md
2. docs/阶段0_研究与数据规范.md

4. 本任务目录 README.md

必须使用 templates/external-ai/ 中的模板，返回完整任务目录，而不是只在聊天中总结。

过程要求：
- 不修改、移动、重命名或删除 PROJECT_CHARTER.md；
```

## 9. 用户如何把成果交回 Codex

建议将每个任务目录整体压缩为 `<TASK-ID>.zip`，不要拆散文件，也不要只复制聊天内容。交回时可直接说：

```text
这是外部 AI 完成的 <TASK-ID> 任务包。请按阶段 0 规范进行：
1. 检查文件完整性和范围；
2. 读取 HANDOFF、QA 和 ISSUES；
3. 抽样复核成果；
4. 给出 pass/revise/reject；
5. 通过后更新 TASKS，并决定是否进入暂存数据或下一任务；
6. 只把可公开的项目文档和结构化摘要提交 GitHub，不上传原始书籍或整书 OCR。
```

## 10. Codex 汇总时的读取顺序

Codex 收到任务包后按以下顺序处理，以节约用量：

1. `README.md`：确认任务范围和 Agent；
2. `STATUS.md`：确认执行是否完整、是否曾阻塞；
3. `HANDOFF.md`：快速了解完成、未完成和下一步；
4. `QA_REPORT.md` 与 `REVIEW.md`：判断是否可用；
5. `ISSUES.md`：识别需要决策的问题；
6. `MANIFEST.md`：核对文件是否齐全；
7. 最后才读取较大的 `OCR.md` 或 CSV，并优先抽样而不是从头重复处理。

## 11. 退回修订的标准指令

如果任务不合格，Codex 可以只给外部 AI 以下结构化返修单：

```text
任务 ID：<TASK-ID>
结论：revise / reject
必须修复：
1. <文件 + 页码/行号 + 问题>
2. <文件 + 页码/行号 + 问题>

保持不变：<已经通过的范围>
禁止新增：<不得扩大的范围>
重新验证：<抽样页或检查项>
返修后更新：STATUS.md、QA_REPORT.md、ISSUES.md、HANDOFF.md、MANIFEST.md。
```

## 12. 推荐的第一轮外部 AI 任务

在 N1 通过并收到 5—10 份资料后，按以下顺序派发：

1. 一个 `EXT-CATALOG` 完成全部文件的接收清单；
2. Codex 分配正式来源 ID；
3. 按来源拆分 2—3 个建档任务；
4. 按来源拆分 2—3 个 L1 OCR 任务；
5. 用另一个 AI 对其中至少一个 OCR 包做独立质检；
6. Codex 只读取交接包和抽样内容，形成阶段 1 首批汇总；
7. 再为博尔赫斯和李斯佩克朵建立 N2 试点任务卡。

不要一开始就把全部资料交给一个 AI 做整书 OCR。小批次更容易发现页码、格式和质量问题，也更方便返修和汇总。
