# 章程修改提案：GitHub 收口方式

- 提案日期：`2026-08-04`
- 对象：`PROJECT_CHARTER.md`
- 用户明确授权：“我批准修改 PROJECT_CHARTER.md：GitHub 改为仅在我明确通知上传时才提交和上传，不再按每个任务自动处理。”

## 修改原因

项目处于多个小任务连续交付阶段。逐任务进行 Git 提交和 GitHub 上传会增加用量与收口成本，也不利于在公开前对版权边界进行集中检查。

## 旧规则与新规则

| 项目 | 旧规则 | 新规则 |
|---|---|---|
| Git 提交/上传时机 | 每个可独立说明且通过检查的公开修改应提交上传 | 本地累积并完成审计；仅在 USER 明确通知“上传”或“提交并上传”时，由 Codex 将已通过、可公开的变更批量提交与上传。 |
| 版本记录 | 每次修改独立发布 | 每个上传批次仍必须更新 README、决策记录和 CHANGELOG，列明累积的实际变更。 |
| 公开边界 | 原有限制 | 不变；所有批次上传前仍需过滤原书、整书 OCR、私人资料和未授权摘录。 |

## 影响与迁移

- 影响：`PROJECT_CHARTER.md` 第 21、23.3、24 节，以及 README、决策记录、CHANGELOG、任务卡中的 GitHub 执行说明。
- 不影响：任何研究范围、数据结构、候选内容、来源 ID、OCR级别、版权边界或 N1—N4 用户节点。
- 无数据迁移或返工；已累积的本地变更将在用户下次明确通知后作为一个公开批次审计、提交与上传。

## 风险与防护

- 风险：本地未上传的修改会累积。
- 防护：每次上传前必须输出可公开文件清单、差分、版本记录和未解决问题；用户可在上传前一次性查看变更范围。
- 备选案：保留逐任务上传。用户已明确未选择。
