# 拉丁美洲文学地图：研究、OCR、来源与数据规范

版本：0.4.0

状态：阶段 0 试行规范；数据 Schema 将在 N2 后冻结

> 本规范服从仓库根目录 `PROJECT_CHARTER.md`。总章程是最高冻结文件，未经用户明确授权，任何 AI 不得修改。

## 1. 适用范围

本规范适用于所有参与 V1 的 Codex、外部 AI、OCR 工具、人工整理者和 Reviewer。任何任务如果没有更具体的任务卡，均以本规范为最低要求。

## 2. 核心原则

1. 来源优先：没有明确来源 ID 和来源题名的内容不能进入已确认数据。
2. 忠实转录：OCR 不进行文学改写，不用常识填补缺字。
3. 候选与事实分离：外部 AI 抽取结果默认是候选，只有通过审核和整合后才成为主数据。
4. 原件不变：不覆盖、不裁剪、不重命名用户原始文件。
5. 单一主数据：未来 SQLite 是唯一主数据，外部 AI 不直接修改。
6. 最小公开：公开仓库不保存原书、整书 OCR、隐私和敏感配置。
7. 全程留痕：每项工作必须有任务 ID、Agent 归属、过程状态、问题和交接记录。

## 3. 目录与交接边界

推荐本地目录：

```text
inputs/private/                 # 原始资料，仅本地，禁止提交
work/external-ai/<TASK-ID>/     # 外部 AI 的任务工作包，仅本地
handoffs/incoming/<TASK-ID>/    # 用户收回的外部 AI 交接包，仅本地
data/staging/                   # 待审核结构化结果
data/master/                    # 未来主数据库，只由整合者写入
data/exports/                   # 由主数据库生成的审核表和 JSON
docs/reports/                   # 可公开的质量摘要和节点报告
templates/external-ai/          # 可复制的任务与交接模板
```

`inputs/private/`、`work/` 和 `handoffs/incoming/` 默认不得进入公开 GitHub。是否公开单项成果由 Codex 在去除版权文本和敏感内容后判断。

## 4. 标识与命名

### 4.1 任务 ID

格式：`V1-<阶段>-<三位序号>`。

示例：

- `V1-S1-001`：阶段 1 的第一个资料盘点任务；
- `V1-S2-003`：阶段 2 的第三个试点任务；
- `V1-S3-012`：阶段 3 的第十二个批次任务。

### 4.2 来源 ID

格式：`SRC-<四位序号>`，如 `SRC-0001`。同一物理或数字版本只建立一个来源记录；不同译本、版次或文件分别编号。

### 4.3 实体候选 ID

外部 AI 暂存 ID：`CAND-<类型>-<四位序号>`，如 `CAND-AUTHOR-0001`。主数据稳定 ID 由 Codex/整合者在审核后分配，外部 AI 不得自行沿用暂存 ID 作为正式 ID。

### 4.4 文件命名

任务包目录固定为 `<TASK-ID>_<简短中文主题>`。目录内文件使用模板规定的固定英文文件名，正文可用中文，避免不同 AI 随意改名。

## 5. 来源记录规范

每份来源至少记录：

- `source_id`；
- 题名与副标题；
- 作者、编者或机构；
- 译者；
- 出版社、出版地、出版年、版次；
- ISBN、DOI 或稳定 URL（如有）；
- 语言；
- 文件格式、页数和文件名；
- 资料类型；
- 来源等级；
- 使用限制和版权提示；
- OCR 状态；
- 最低引用方式：书籍记录书名，论文记录论文题名及 DOI/稳定 URL（如有），网页记录页面标题和 URL；
- 章节、页码或电子位置（可选增强）；
- 处理 Agent、处理日期和任务 ID。

### 5.1 来源等级

| 等级 | 类型 | 可承担的用途 |
|---|---|---|
| A | 原著、学术专著、同行评议论文、大学出版社 | 可支持核心事实和解释性判断 |
| B | 图书馆、出版社、作家基金会、大学研究中心 | 可支持书目、人物和背景事实 |
| C | 权威媒体、专业书评、可靠访谈 | 可作补充背景或观点来源 |
| D | 普通网页、百科聚合、无署名材料 | 仅作线索，不得作为解释性观点唯一依据 |

### 5.2 网络来源

必须记录页面标题、作者/机构、URL、发布日期（如有）、访问日期和页面用途。链接失效时保留原 URL，并在问题清单中标记。

## 6. OCR 规范

### 6.1 转录层级

| 层级 | 说明 | 适用任务 |
|---|---|---|
| L0 | 文件可读性和文字层检查，不做全文 OCR | 资料盘点 |
| L1 | 目录、版权页、索引和任务指定内容 OCR | 快速建档、试点准备 |
| L2 | 与研究问题相关的内容单元 OCR | 研究证据提取；页码锚点可选 |
| L3 | 全文 OCR，按章节拆分并做质量抽样 | 仅经任务卡明确授权时 |

外部 AI 不得自行把 L1/L2 扩大到整书 L3。

### 6.2 页面锚点（可选）

页面锚点不再是默认强制项。只有任务卡特别要求、现成文字层可直接保留，或研究者确实需要逐页核查时，才在原始页面起始处使用：

```markdown
<!-- page: 12 -->
```

电子书如需要详细定位，可使用章节名和电子位置：

```markdown
<!-- chapter: 第一章；location: 356-420 -->
```

### 6.3 版式保留

- 保留标题层级、段落、列表、脚注编号和图表标题；页码锚点仅按任务卡要求保留。
- 页眉页脚如果反复出现，可删除，但必须在 OCR 质量报告中说明。
- 双栏、边注、脚注顺序不确定时不得猜测，写入问题清单。
- 表格优先转为 Markdown 表格；复杂表格可保留为逐行文本并标记结构问题。
- 图片只记录图号和图题；页码可选，不进行无授权的图片再发布。

### 6.4 错误与校正

- 明确 OCR 错字可在核对原页后修正，不保留明显机器乱码。
- 无法辨认写作 `[无法辨认]`；可能值写入 `ISSUES.md`，不直接放进正文。
- 疑似原书错误使用 `[原文如此]`，不得静默改写。
- 不现代化原文拼写，不统一作者有意使用的标点或语体。
- 专名校正必须有原页或权威书目依据。

### 6.5 OCR 抽样质量

每个任务至少抽查开头、中部、结尾的代表性内容单元；大任务按任务卡增加抽样。记录：

- 抽查文件、章节、页面或内容单元标识（选择现成且最省成本的方式）；
- 字符错误、漏段、错序、脚注和表格问题；
- 估计准确率；
- 是否达到可研究标准；
- 是否需要重做。

最低门槛：正文抽样准确率建议不低于 98%；专名、数字、年份、作品名和来源题名必须重点核对。页码不属于默认重点字段。

## 7. 结构整理规范

- Markdown 只表达原文结构，不重新写作原文内容。
- 标题使用 `#`—`####`，不得为了美观改变层级。
- 跨页段落合并时保持语序完整；只有任务卡要求时保留中间页面锚点。
- 脚注使用 `[^1]` 形式；无法关联的脚注保留原编号并标记。
- 删除广告、下载站推广和无关导航时，在质量报告中列明删除类型。
- 同一任务不得同时交付“原始 OCR”和“润色版”而不标明区别；默认只交付忠实整理版。

## 8. 候选数据抽取规范

### 8.1 核心实体类型

- `Author`：作家；
- `Work`：作品；
- `Place`：地点；
- `Movement`：文学运动；
- `Event`：事件；
- `Theme`：主题；
- `Source`：资料来源；
- `Evidence`：证据片段或释义。

### 8.2 候选实体字段

至少包括：候选 ID、实体类型、规范名称候选、原文名称、别名、语言、国家/地区、时间信息、来源 ID、来源题名、置信度和问题说明。页码/章节、原文短摘录或释义为可选增强字段。

### 8.3 候选关系字段

至少包括：主体候选、关系类型、客体候选、研究说明、来源 ID、来源题名、置信度、争议状态和提取 Agent。详细定位和证据释义为可选增强字段。

外部 AI 只提交候选关系，不得把“受到影响”“代表某运动”“体现某主题”等解释性关系写成无条件事实。

## 9. 受控词表（阶段 0 试行版）

### 9.1 语言

`zh` 中文、`es` 西班牙语、`pt` 葡萄牙语、`en` 英语、`fr` 法语、`other` 其他。

### 9.2 资料类型

`primary_work` 原著、`book` 专著、`chapter` 书籍章节、`journal_article` 论文、`thesis` 学位论文、`reference` 工具书、`interview` 访谈、`institutional_web` 机构网页、`media` 媒体、`other` 其他。

### 9.3 处理状态

`received` 已接收、`inventoried` 已建档、`ocr_pending` 待 OCR、`ocr_done` OCR 完成、`qa_failed` 质检未通过、`qa_passed` 质检通过、`extracted` 已抽取候选、`reviewed` 已复核、`integrated` 已整合、`deferred` 延后。

### 9.4 置信度

`high`：原文直接明确支持；`medium`：来源基本支持但需复核；`low`：仅为线索或存在歧义。

### 9.5 争议状态

`none` 无已知争议、`needs_second_source` 需第二来源、`disputed` 来源冲突、`unclear` 含义不清、`rejected` 已否决。

### 9.6 关系类型候选

| 类别 | 关系词候选 |
|---|---|
| 创作与出版 | `CREATED`、`PUBLISHED_IN`、`TRANSLATED_BY` |
| 地域 | `BORN_IN`、`LIVED_IN`、`SET_IN`、`ASSOCIATED_WITH_PLACE` |
| 文学史 | `MEMBER_OF`、`ASSOCIATED_WITH_MOVEMENT`、`PARTICIPATED_IN_EVENT` |
| 主题 | `EXPLORES_THEME`、`RESPONDS_TO_EVENT` |
| 影响与回应 | `INFLUENCED_BY`、`INFLUENCED`、`RESPONDS_TO_WORK` |
| 版本与改编 | `TRANSLATION_OF`、`EDITION_OF`、`ADAPTED_FROM` |

该词表在 N2 试点后可能合并、拆分或改名。外部 AI 不得自行新增关系词；无法归类时填 `PROPOSED:<中文说明>`。

## 10. 过程文档与交接包

任务卡必须声明 `package_profile`：

- `LITE`：用于 ID 回填、书目核对、覆盖统计和格式检查。交付任务说明、主体成果和 `HANDOFF.md`；HANDOFF 内合并记录状态、QA、问题、文件清单和下一步。
- `FULL`：用于 OCR、研究抽取、关系审核、数据库迁移和高版权风险任务。交付 `README.md`、`STATUS.md`、主体成果、`QA_REPORT.md`、`ISSUES.md`、`HANDOFF.md`、`MANIFEST.md`；独立复核另含 `REVIEW.md`。

两种模式都必须保存任务 ID、Agent 归属、状态、验证、问题和交接。缺少任务 ID、来源 ID、来源题名、QA 信息或 HANDOFF 的结果不得直接整合；缺少页码或章节本身不再阻塞。

### 10.1 节省 Token 的执行顺序

1. 外部 AI 以任务卡为完整指令；聊天中只发送任务 ID、任务卡路径、输入/输出路径和回复格式。
2. Worker 交付前先运行机械检查；能从 CSV 自动计算的数字不得手工抄写。
3. Codex 先读 README/HANDOFF，再读 QA/ISSUES/MANIFEST，最后抽样主体成果。
4. 返修只处理失败项，返修单必须写明保持不变和禁止新增范围。
5. 只有 `TASKS.md` 保存实时状态；其他总览文档按里程碑批量同步。

## 11. Reviewer 检查清单

- 任务范围是否与任务卡一致；
- 是否遗漏输入文件或任务范围；
- 任务卡特别要求的 OCR 页码锚点是否可回查；未要求时不检查；
- 专名、年份、数字和作品名是否抽查；
- 删除或改写是否有说明；
- 候选事实是否有明确来源 ID 和来源题名；
- 是否把推测写成事实；
- 是否包含版权全文、隐私、密钥或不应公开的材料；
- 过程文档是否齐全；
- HANDOFF 是否足以让未参与执行的 Codex继续工作。

## 12. 失败与退回条件

出现下列任一情况，任务包退回：

- 任务卡特别要求页码锚点但大量缺失或无法对应原文件；
- 原文被总结、润色或重写，无法作为 OCR 使用；
- 关键专名、数字或引文未经核对；
- 候选数据没有来源 ID 和来源题名；
- 外部 AI 声称已确认但没有证据；
- 文件命名混乱、成果只有聊天摘要而无文件；
- 缺少 QA、问题清单或交接记录；
- 包含未经授权的公开上传、版权全文或敏感信息。

## 13. 规范变更

普通格式补充由 Codex记录在 CHANGELOG 后执行；影响实体、关系、来源等级或主数据兼容性的变更必须在决策记录中说明，并在 N2 后建立迁移记录。
