# 拉丁美洲文学地图：项目章程

版本：0.3.1

日期：2026-08-04

状态：阶段 0 支持文档

> 项目最高、冻结治理文件为仓库根目录 `PROJECT_CHARTER.md`。本文件保留阶段 0 的形成背景和早期基线；如与总章程冲突，以 `PROJECT_CHARTER.md` 为准。未经用户明确授权不得修改总章程。

## 1. 项目使命

建设一套面向中文读者、来源可追溯、可持续扩展的拉丁美洲文学内容数据库。数据库用于连接作家、作品、国家、城市、文学运动、历史事件和主题，并作为后续文学地图、时间轴、关系图和数字展览的唯一内容底座。

项目首先解决“资料是否可靠、关系是否有证据、内容能否复用”的问题，再解决网站呈现问题。V1 不开发网站、小程序、账户系统或 AI 问答。

## 2. V1 成功标准

V1 计划形成：

- 约 10 位核心作家；
- 约 30 部核心作品；
- 10 个主题；
- 约 6 个文学运动；
- 约 12 个文学或历史事件；
- 至少 150 条经过审核、有来源依据的实体关系；
- 覆盖约 7 个国家或地区；
- 至少包含 3 位女性作家，并包含葡萄牙语文学；
- SQLite 规范数据库、Excel/CSV 审核表和网站 JSON；
- 数据字典、来源目录、质量报告、决策记录和变更日志。

“约”表示允许根据材料质量在 N2 或 N3 小幅调整，任何显著扩张必须新增项目决策。

## 3. V1 范围

### 3.1 范围内

- 作家、作品、地点、文学运动、事件、主题、来源和证据八类核心实体；
- 作家与作品的基础书目信息、规范名称和别名；
- 有来源支持的创作、出版、地域、参与、主题、影响和回应关系；
- 中文研究摘要、作家卡、作品卡和主题说明；
- 用户提供资料的 OCR、结构化整理、来源登记和证据定位；
- 必要的学术、图书馆、出版社、基金会和其他权威公共资料补证；
- 争议、缺口、不确定性和版本变化记录。

### 3.2 范围外

- 网站、小程序和移动应用开发；
- 用户账户、评论、推荐和支付功能；
- 面向公众的生成式 AI 问答；
- 全量拉丁美洲文学百科；
- 未经授权的作品全文、整书 OCR 公开传播或大段版权文本；
- 无来源的文学影响判断、价值排名和确定性结论。

该名单是 N1 审核基线，不是不可修改的最终名单。替换时优先维持国家、语言、性别、时代和体裁的整体平衡。

### 4.2 十大主题

1. 迷宫、时间与无限
2. 魔幻现实与现实观
3. 权力、独裁与国家暴力
4. 记忆、遗忘与历史
5. 革命、流亡与边界
6. 城市与现代性
7. 乡土、边疆与民族身份
8. 语言实验与叙事形式
9. 性别、身体与主体
10. 正义、复仇与审判

### 4.3 策展原则

V1 采用“均衡文学地图”路线，不以魔幻现实主义、政治法律或形式先锋中的任何一项覆盖全部拉美文学。数据结构同时保留“权力与正义”和“形式与先锋”两个后续专题的扩展能力。

## 5. 治理与决策权

| 角色 | 主要职责 | 不得自行执行 |
|---|---|---|
| 用户 | 在 N1—N4 决定范围、模型、候选版和正式发布 | 不需要逐条审核 OCR、关系或普通纠错 |
| Codex 项目经理 | 维护任务源、规范、Schema、验收、整合、版本和 GitHub | 不越过用户节点作方向性或公开发布决定 |
| 外部 AI Worker | OCR、结构整理、来源登记、候选抽取和机械核对 | 不改主数据库、不发布 GitHub、不把候选写成已确认事实 |
| Reviewer | 检查来源、页码、格式、范围和错误 | 不审核自己完成的任务包 |
| 数据整合者 | 将通过审核的暂存成果写入主数据库并导出 | 不接收缺少交接文档或证据定位的结果 |

## 6. 用户审核节点

| 节点 | 进入条件 | 用户需要决定 | 通过后的效果 |
|---|---|---|---|
| N1 范围基线 | 阶段 0 文档齐备 | V1 范围、作家候选、主题和资料策略 | 可启动资料盘点与 OCR，不再逐批确认 |
| N2 模型试点 | 两位作家、约 6 部作品、20—30 条关系完成试点 | Schema、关系强度和中文风格 | 冻结 V1 Schema，开始批量研究 |
| N3 V1 候选版 | 全量候选数据、覆盖矩阵和质量报告完成 | 是否存在方向性调整 | 进入最终修订与冻结 |
| N4 正式发布 | 发布包、版本摘要和已知问题齐备 | 是否正式发布 V1 | 创建版本标签并进入 V2 评估 |

## 7. 资料与版权边界

- 用户提供的 PDF、EPUB、扫描件和原始书籍只在本地或用户指定的私有空间处理。
- 公开仓库只保存项目文档、结构化数据、书目信息、释义、必要短摘录和引用定位。
- 外部 AI 不得把原始资料上传到未经用户授权的公开服务或公开链接。
- 无法确认的文字标记为 `[无法辨认]`，不得猜测补全。
- 解释性或争议性关系原则上需要两项独立可靠来源；否则标记为“待证”或“争议”。

## 8. 数据与交付原则

- SQLite 是未来唯一主数据；Excel/CSV 和 JSON 均由主数据生成。
- V1 Schema 在 N2 通过后冻结；N2 前的字段均属于试行版。
- 外部 AI 只向任务暂存包写入结果，不直接编辑未来主数据库。
- 所有成果必须能追溯到来源 ID、页码/章节/电子位置或 URL 与访问日期。
- 每个任务必须有状态记录、质量报告、问题清单和交接说明。

## 10. 章程变更规则

本节是阶段 0 的早期规则。`PROJECT_CHARTER.md` 建立后，其第 23 节“本章程的变更程序”具有最高效力；未经用户明确授权不得修改总章程。

任何影响项目目标、V1 范围、数据结构、公开边界、用户节点或重大成本的变化，必须：

1. 在 `拉丁美洲文学地图_项目决策记录.md` 新增或取代一项决策；
2. 在 `CHANGELOG.md` 记录实际修改；
3. 标明受影响的任务、数据和交付物；
4. 在适用的用户审核节点获得确认；
5. 完成验证后提交并上传 GitHub。
