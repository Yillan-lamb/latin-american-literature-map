## 1. 修改原因

原规则要求本地书籍证据定位到页码、章节或电子位置，OCR 逐页写入锚点。实践表明，这会把大量时间和 Token 消耗在逐页编号、锚点维护和跨文件同步上，且已造成多轮与页码、锚点和摘要数字有关的返修。

用户明确决定把 V1 的最低证据定位粒度调整为“来源级”：书籍能够回到具体书名，论文能够回到具体论文名，网页能够回到页面标题和 URL 即满足最低要求；章节、页码、电子位置和短摘录作为可选增强信息，不再是任务验收、候选暂存或主数据准入的强制门槛。

## 2. 旧规则与新规则

| 事项 | 旧规则 | 新规则 |
|---|---|---|
| 书籍证据 | 必须记录章节、页码或电子位置 | 必须记录来源 ID 和书名；章节、页码可选 |
| 论文证据 | 通常要求页段或章节定位 | 必须记录来源 ID、论文题名及 DOI/稳定 URL（如有）；页码可选 |
| 网页证据 | URL、页面信息、访问日期并尽量定位栏目 | 页面标题、机构/作者、URL、访问日期；DOM/段落锚点可选 |
| OCR | 每一原页强制页码锚点 | 按来源或任务范围忠实整理；逐页锚点仅在任务卡特别要求时使用 |
| 候选字段 | locator 和证据摘录强制 | source_id 与 source_title 强制；locator 与摘录可选 |
| 入库门槛 | 缺少 locator 不得进入暂存 | 缺少有效来源标识不得进入；详细 locator 不再阻塞 |

## 3. 工作流效率调整

1. 建立 `LITE` 与 `FULL` 两种任务包：机械书目、ID 回填、覆盖统计使用轻量包；OCR、研究抽取、关系审核和数据库迁移使用完整包。
2. 返修采用差量模式：只修改未通过项，明确保持不变范围和重新验证项。
3. 外部 AI 启动提示词缩短为任务卡路径、输入路径、交付路径和完成回复格式；详细规范保留在任务卡。
4. 增加本地机械检查脚本，优先验证文件完整性、CSV 结构、危险文件、ID 重复和来源字段，Codex 聚焦语义与抽样。
5. 动态状态只更新 `project/tasks/TASKS.md`；README、决策记录和 CHANGELOG 在里程碑或用户通知上传时批量同步。
6. GitHub 继续遵守用户触发的批量上传规则，本次修改只在本地完成。

## 5. 风险与防护

- 风险：来源级定位降低了逐句复核精度。
- 防护：解释性关系仍原则上需要两项独立可靠来源；来源 ID、完整题名、来源等级和争议状态仍为强制字段。
- 风险：外部 AI 可能只写模糊书名。
- 防护：必须关联正式来源登记；论文和网页必须保留题名及 DOI/稳定 URL（如有）。
- 风险：不同任务包过度精简导致交接丢失。
- 防护：无论 LITE/FULL，任务 ID、状态、主体成果、QA、问题和 HANDOFF 信息不得缺失；LITE 只合并文件，不删除信息。
