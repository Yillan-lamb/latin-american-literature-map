# 章程修改提案：治理同步与 Web 版本规则

- 提案日期：2026-09-02
- 用户批准：USER 于 2026-09-03 明确批准本主题与范围
- 目标文件：`project/governance/PROJECT_CHARTER.md`
- 目标版本：`1.6.0 → 1.7.0`

## 修改原因

WCD-07 PR #23 合并后，tasks、decision、CHANGELOG、README 与当前网站版本信息没有作为同一治理包同步收口。用户进一步明确：每个完成 PR 或重大项目进展都必须同步修订治理文件和网站当前信息；没有新增读者内容时不得机械提升 Web minor 版本。

## 旧规则与新规则

| 项目 | 旧规则 | 新规则 |
|---|---|---|
| PR/重大进展同步 | 主要在里程碑、重要决策或预定义节点批量同步 | 每个完成 PR 或重大进展同步 tasks、decision、CHANGELOG、README、当前网站版本与受影响 Web 元数据；普通小步骤不单独制造版本噪音 |
| Web 版本 | 按阶段示例演进，未明确内容变化与增量的判定 | 无新增 reader-facing 内容的治理/文档/修复/Research-only 变化使用 patch；新增公共内容或实质能力使用 minor；破坏契约或 USER 批准 Public Release 才考虑 major |
| 独立版本 | Research、Schema、Web Data schema 各自维护 | 明确三者继续独立，不因 Web 版本自动升级 |

## 影响的阶段、任务、数据和交付物

- WCD-07 当前 Web 从 `0.3.3` 修订为 `0.3.4 Development`；Research `Data 1.5.0`、Schema `0.4`、Web Data schema `v2-web-0.2` 保持。
- 更新 `project/tasks/V2_TASKS.md`、决策记录、`CHANGELOG.md`、README、package 元数据、构建/验证/部署脚本、生成的 Web JSON、WCD-07 审计和本章程。
- 六个 P0、29 admitted facts、6 CREATED、17/17 P1 `DEFER`、Public Release 暂停和“不创建 WCD-08”均保持。

## 迁移或返工

## 风险与备选方案

- 风险：历史文档中的旧 Web 版本若被误改，会破坏时间线。处理方式是保留历史条目，只在当前状态、当前元数据和新增治理记录中写 `0.3.4`。
- 风险：将 Research layer 数量误读为公共内容扩张。处理方式是明确 public reader scope 未变，并要求以内容/能力变化而不是数据量机械决定 minor。
- 备选方案：继续维持 `0.3.3` 可避免版本变更，但会使当前网站元数据、tasks 和治理记录继续不一致，故不采用。
