## 1. 审计方法与基线

本审计直接读取 V1 正式主库和 V1.0.0 发布快照的表结构、实体类型、关系、事实、内容卡、来源和缺口，不以 README、聊天记录或模型常识推断数据状态。主库验证命令：

```text
python3 scripts/validate_master.py data/master/V1_MASTER.sqlite
```

结果为 `pass`，`schema_version=0.3`，SQLite `integrity_check=ok`，外键错误为 0。正式数据规模为：

| 数据对象 | 数量 | V2 适配判断 |
|---|---:|---|
| sources | 74 | 可用于研究层来源目录；可生成来源摘要 |
| entities | 144 | 可生成基础搜索索引和页面候选，但须按实体类型过滤 |
| relationships | 76 | 可用于正式页面关联、地图关系和轻量探索 |
| relation_holds | 40 | 仅进入研究状态说明，不进入普通正文关系 |
| facts | 238 | 是研究素材层，不能无差别作为前端事实流 |
| content_cards | 40 | 可作为 V2 阅读层的主要初始内容来源 |
| relationship_evidence | 91 | 可生成关系研究依据 |
| gaps | 13 | 可生成研究缺口和状态管理输入，不直接生成普通正文 |

实体类型分布为：`author` 14、`work` 28、`collection` 11、`place` 22、`theme` 29、`movement` 8、`event` 5、`character` 10、`person` 5、`institution` 6、`adaptation` 4、`edition` 2。

这里的 14 位 `author` 包含 10 位核心作家和 4 位仅作为研究关联对象出现的外部作者；28 个 `work` 与 11 个 `collection` 不能简单合并为 30 部作品，前端必须保留 V1 已确定的实体分层。

## 2. 当前可以直接用于网站的数据

### 2.1 直接可用的研究数据

以下数据可以直接进入 Web Data 构建的输入层：

1. 规范实体的稳定 ID、中文名、原文名和实体类型；
2. 76 条 `relationships`，其状态为 V1 发布包认可的正式关系，可用于页面关联、基础搜索关联和轻量文学探索；
3. 关系对应的 `relationship_evidence`、`relationship_sources` 和正式来源记录，可用于可展开研究层；
4. 通过关系表建立的作者—作品、作品—地点、作者—地点、作品—主题、作品—事件等已审核关联；
5. 内容卡中明确的中文资料卡和书目信息；
6. 来源目录、研究状态、hold 和 gap 的结构化状态，用于研究层和构建 QA；
7. 作者生卒年、作品/作品集出版年、体裁、语言、国家/地区等已存在且有来源关联的基础字段，但必须按事实准入状态和策展规则筛选。

### 2.2 不能直接当作普通正文的数据

`facts` 表中的 238 条记录具有不同的 `admission_status`：`accepted_for_n2` 50、`batch_retained_candidate` 161、`candidate_for_staging_review` 20、`hold` 2、`research_note_only` 1、`gap` 2、`not_work_level` 1、`pending_n3` 1。因此，前端不能把整张 `facts` 表当作正式事实 API；严格的 Web Data 构建应区分已准入事实、保留候选、研究说明和缺口。

同样，40 条关系 hold、13 条 gap、政治诗歌的 `hold×3 / 作者级×1 / gap×1` 分层、《消逝的足迹》1953 年书目 hold 以及 author→event 说明级边界，均不得被页面写作自动确定化。

### 3.3 地点页

V1 有 22 个 `place` 实体，21 个至少参与 1 条正式关系，1 个（墨西哥城）没有正式关系。现有地点关系共 25 条：17 条作者—地点 `ASSOCIATED_WITH_PLACE`，8 条作品—地点 `SET_IN`；没有 place 内容卡，也没有 place 事实。

因此，地点数据目前可以直接生成：

- 21 个有正式文学关系的“地点关系页骨架”；
- 国家到地点的关系候选列表；
- 作品故事空间和作家地理的研究证据入口。

但不能直接生成完整的文学地点导读页。国家页、现实地点页和文学虚构空间页都需要 V2 Curation Data 补充文学导语、展示顺序、页面优先级和空间类型。

## 4. 地图数据缺口

V1 `place` 表只有实体 ID、名称、原文名和规范化信息，不具备 V2 地图模型要求的以下字段：

- `place_kind`：country / region / city / locality / fictional_place；
- `reality_status`：real / fictional；
- `latitude`、`longitude`；
- `coordinate_source`、坐标检索/更新时间；
- `parent_place_id`，用于国家 → 地点两级层级；
- `map_status`：featured / eligible / hidden；
- 地图展示顺序、国家代码、现实/虚构视觉标识；
- 结构化 `map_relation_role`，用于区分 birth、residence、writing、exile、major_literary_association、story_setting、fictional_setting。

V1 的 17 条 `ASSOCIATED_WITH_PLACE` 虽有中文描述和来源，但没有受控的地图角色字段；8 条 `SET_IN` 可以作为作品故事空间候选，但仍需在 V2 构建层统一映射为页面可消费语义。

V1 没有以下已审核的文学地点关系：

1. 作家与地点的 birth / childhood / residence / writing / exile 等细分关系；
2. 作品与地点的现实故事空间、虚构故事空间的结构化区分；
3. 文学虚构空间与现实地点的研究关联关系；
4. 国家与子地点的 parent 层级关系；
5. 地点进入地图、国家页或完整地点页的策展状态。

上述缺口不允许由前端硬编码补齐，进入 `V2-S1-002` 地图数据补充与 QA。

## 5. 策展字段缺口

V1 `content_cards` 是研究型资料卡，不是 V2 完整策展层。至少需要新增独立的 Curation Data 字段：

### 作者

页面导语、核心主题排序、入门作品及理由、展示标签、首页精选状态、展示顺序、策展状态和依据来源。

### 作品与作品集

一句话导语、无/轻剧透简介、“为什么值得读”、核心主题排序、空间展示说明、延伸阅读对象及推荐理由、策展状态和依据来源。

### 地点

文学导语、地点页优先级、核心作者、核心作品、国家页展示顺序、地图展示状态、空间类型、现实/虚构标识、坐标来源和页面状态。

### 首页与时间线

精选作家、精选作品、策展阅读入口、专题标题与导语、文学时期、时期顺序、时间节点筛选、节点优先级和节点导语。

### 审核与可追溯字段

`review_status`（`auto_approved` / `user_review` / `hold`）、`draft_source_ids`、`research_basis`、`review_note`、`reviewed_by`、`reviewed_at`、`content_version` 和 `generated_at`。

这些字段应在 `V2-S2-001` 建立，不写入 V1 Research Data，不改变 V1 事实和正式关系。

## 6. AI 策展准入分层

### 可由 AI 生成、核验后自动准入

- 基于已审核内容卡和事实的作者/作品/国家/地点导语草稿；
- 对已有正式关系的自然语言转换；
- 由已存在的作者、作品、主题、地点和来源生成的页面标签、摘要和研究层说明；
- 基于已审核出版年和文学实体的基础时间线节点说明；
- 基于已有关系的页面关联卡，不新增研究关系。

统一流程为：`AI 生成 → 来源核验 → Codex 审核 → auto_approved`。

### 必须进入 `USER_REVIEW`

- 跨作品“读完之后读什么”的推荐与推荐理由；
- “如果喜欢 A，可以读 B”等阅读路径；
- 新的作家地位概括、跨作家比较和强价值判断；
- 数据库没有现成依据的新主题归纳；
- 文学虚构空间与现实地点的解释性联系（若不能由现有来源直接支持）。

### 必须保持 `hold`

- 5 个 `not_found` 研究缺口、未关闭的作品级研究缺口和《消逝的足迹》1953 书目问题；
- 40 条关系 hold 及其派生的确定性表述；
- 没有正式文学关系的地点页面事实；
- 未经可靠公开来源核验的现实地点坐标；
- 任何把作者级政治材料下推为具体作品主题的内容；
- 任何为完整页面而新造的研究事实或文学关系。

## 7. N2 样本建议

根据“内容卡为 `meets`、作者和作品关系较完整、地点具有现实/虚构对照价值、且包含葡萄牙语文学”的条件，建议 N2 优先从以下三国三位作家、六部作品中选择：

| 国家 | 作家 | 作品候选 | 可验证的文学空间 |
|---|---|---|---|
| 巴西 | 克拉丽丝·李斯佩克朵 | 《活水》《星辰时刻》 | 里约热内卢 |
| 墨西哥 | 胡安·鲁尔福 | 《佩德罗·巴拉莫》；可从其他有卡作者作为补充 | 圣加布里埃尔、科马拉 |
| 哥伦比亚 | 加西亚·马尔克斯 | 《百年孤独》《没有人给他写信的上校》《一桩事先张扬的凶杀案》 | 阿卡塔卡、马孔多 |

由于胡安·鲁尔福当前只有 1 个 `meets` 的作品卡，若必须凑满 6 部“直接可读”的作品，可将《小径分岔的花园》或《阿莱夫》作为第四位作家/阿根廷扩展样本；这属于样本组合选择，不改变研究数据。

最小稳妥闭环是 3 位作家、6 部 `meets` 作品、3 个国家、2 个现实地点页和 2 个文学虚构空间页。最终样本由 `V2-S3-001` 根据地图 QA 和策展包完成后登记。

## 8. 当前是否阻断 V2-N2

**当前不存在需要 USER 立即决策的产品或研究阻断。**

存在但可按已批准顺序自主处理的前置缺口：

1. 地点的 V2 技术字段、可靠坐标和 parent 层级尚未建立；
2. 21 个关系-backed 地点没有独立地点卡；
3. Curation Data 和 Web Data Schema 尚未建立；
4. 真实 N2 样本集和最小策展包尚未登记；
5. 作品页、地点页和时间线的阅读层文字需要从正式数据中做受控转换。

这些问题正是 `V2-S1-002`、`V2-S2-001`、`V2-S2-002`、`V2-S3-001` 和 `V2-S3-002` 的已定义产物，不需要在本审计阶段扩大 V2.0 范围或修改 V1 研究标准。

## 9. 结论

V1.0.0 已足以支撑一个真实数据驱动的 N2 原型：10 位核心作家页、17 个来源状态为 `meets` 的作品页、25 条文学地点关系、基础搜索和研究层入口均有正式数据基础。V1 尚不足以直接支撑完整地点页、完整地图层级、正式时间线策展和批量阅读推荐；这些缺口均已被清楚分层，下一步按 V2 任务依赖补齐。

**审计结论：`V2-S1-001 = ✅ DONE`。下游解锁 `V2-S1-002`。**
