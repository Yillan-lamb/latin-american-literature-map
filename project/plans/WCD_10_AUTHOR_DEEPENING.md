本节优先于下文较严的历史执行细节；Schema、61作者/21批、来源保真与Public Release边界保持。

## 背景与目标

WCD-11 已将视觉系统集成到正式网站，但现有内容覆盖不等于作品谱系完整。对 Curation `PUBLIC_CONTENT.json` 顺序固定的 61 位核心作家逐一盘点，并补入证据充分、有明确价值的作品、对象级描述与受控关系。机械盘点不是文学覆盖验收。

## 非目标

- 不扩张至叔本华、卡夫卡、切斯特顿等外围影响节点。
- 不追求全集或固定新增数量；无法定位的作品保留缺口。
- 不改变 Schema、现有 USER 策展决定、网站视觉、地图、版权或 Public Release 状态。
- 不把源站评论、书目年份或策展推荐自动升级为文学解释关系。

## 方案

1. 从最新 main 建立隔离 `codex/` 工作区，保留既有用户修改；使用只读 SQLite 查询生成 61 人全量基线与 21 批名单。
2. 每批三位，末批一位；TASK-106 首批为博尔赫斯、李斯佩克朵、加罗。后续须待前批完成全部验收后解锁。启动全项目不取消批次依赖。
3. 盘点现有 CREATED 作品、事实、内容卡、关系、hold/gap、Curation 状态及公共范围；缺少关系不凭名字自动补作者归属。
4. 建立最小候选变更集，包含具体来源对象、访问日期/状态、等级与用途、查重结论、事实原子值、对象级释义和未解决项。Worker 仅使用候选 ID。
5. 作品、作品集、版本、单篇和改编分别查重；书版、首刊、写作、修订年份分字段。来源内明显旁支错年不得传播到目标对象。
6. CREATED/SET_IN 等按直接证据审核；解释性关系逐三元组要求独立来源，不足保持 hold。机构评论可做归属明确的研究释义，不自动成为已确认 EXPLORES_THEME。
7. 候选自检之后独立 Reviewer 给 pass/revise/reject；返修差量复核。普通事实无需逐条 USER 审批；新文学概括、比较和推荐按 Curation 规则 USER_REVIEW。
8. 只有通过复核的候选才由单一 Integrator 分配正式 ID，新增有前置校验的版本化 SQLite migration，重建新版本导出并验证一致性。已有快照不覆写。
9. 研究扩充不自动公开：正式公开作者/作品名单及 USER 决定保留。需要准入的内容独立进入 Curation 流程，重建 Web Data 后检查公共包与适用浏览器行为。
10. Data/Schema/Web 各自根据实际影响判级；仅 Spec、盘点或候选准备不升版。无额外 USER 授权不合并、不建正式 Tag/Release、不部署。

### 后续批次的审核工具补充

追加勘误仍保留全部旧事实和旧来源链。候选验证默认拒绝同对象同字段的不同值；只有主代理独立审核的 `bibliographic_note` 追加勘误可通过显式 conflict_review，绑定候选内容、具体候选 ID/字段/值/来源、全部冲突旧事实及主库 SHA。年份及其他字段不得借此例外通过，缺项、漂移和闲置审核条目均拒绝。builder 必须实际调用同一验证路径并保留审核依据；该入口不构成旧事实的结构化 supersession 或历史证据修复。

通用 checkpoint 入口使用各批次独立 `CHECKPOINT_REVIEW.json`，明确绑定任务、批次、基库、SQL 和映射 SHA；输入路径限同一实现工作区，基库与当前库、公开前后目录必须不同。调用既有共享 QA 核心精确重放并核验全部表和导出，不能用相同计数替代逐值一致。历史批次专用脚本及冻结 SQL/map 保留。验收包括实际新候选 prepare、篡改拒绝、旧批精确重放和独立主库只读检查。

`new_entities.created_description_zh`可选，用于已经证据核验的编纂、选编或日记作者等CREATED角色描述；不新增关系枚举或研究字段。存在时须是非空字符串，builder在既有relationship.description_zh与evidence_note中原样保存；缺省沿用历史作者名/创作/题名模板。具体文案受同一候选SHA审核门禁绑定，主代理须独立核对其直接证据，不能仅因字符串机械有效就准入。实际prepare/SQL/克隆库读回测试必须覆盖限定描述、缺省兼容及无效值拒绝；历史迁移保持不可变。

### 来源登记的未知出版者值

publisher字段必须存在且是字符串；来源未明确出版者时保留空字符串，不从网页host、机构署名或学位授予单位推导出版者。format/language仍须为非空字符串。prepare不得拒绝合法未知值或改变其内容；真实临时候选/Gate→SQL→克隆库读回须证明空publisher保真，missing/null/non-string及无效format/language须拒绝。此约束使用现有Schema字段，不新增枚举、数据政策或公开内容。

### coverage 历史快照保全行

coverage.objects 的准入主行须按完整批次作品 roster 一物一行。已有对象可额外保留一条明确 legacy_object_snapshot 包装行：只有规定的保全字段、research_refs 为空、没有 candidate_facts 或研究引用，entity/facts/卡/关系及全部来源链、hold、gap 与只读基库逐值一致，且主行旧记录一致。新对象不得使用历史包装，缺主行、多主行、多包装、伪造快照及未知对象均拒绝。

迁移映射保留全部原始 coverage；只有主行驱动来源登记与作品级 gap。比较闭包数组时记录顺序不作数据变化；合法历史 origin/temporary ID 不因某批前缀被拒绝。该兼容不放宽候选 SHA、基库 SHA、唯一作品 roster、全A研究说明或独立 SQL/QA 门禁，不改变已有实体/Schema/公开政策。定向测试与真实基库分类必须实际验证后才重试 prepare。

每一条准入主行（含后续新增作品）必须显式具有非空字符串 research_status 与 research_refs 列表；引用必须唯一并解析到已登记候选来源或保全基库来源。source_refs/status 等辅助字段不能替代该接口；不得仅凭来源等级为 A 将书目或内容描述提升为作品级学术准入。目录或机构说明主行（catalog_only/institutional_commentary）必须具有明确非空 remaining，以现有准入状态记录开放的作品级研究缺口；不把它写成全世界不存在研究的判断。作者包审计在整包Gate之前核对该必需字段及唯一主行roster；缺失须修作者包并保留原冻结稿，不能临时删除保全记录或放宽字段门禁。
