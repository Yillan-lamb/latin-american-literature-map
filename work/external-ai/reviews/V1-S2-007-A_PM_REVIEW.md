## 2. 可重复构建说明（非阻塞）

两次在空临时目录重新构建时，JSON 和一致性报告与交付物一致；两次新建 SQLite 也彼此逐字节一致。新建 SQLite 与交付 SQLite 的逻辑表、规范化哈希、文件大小、完整性和外键检查全部一致，但文件头有两个字节不同。

差异位于 SQLite 头部 offset 98—99，属于 offset 96 起记录的 SQLite 写入库版本号的一部分。当前复检环境使用 SQLite 3.53.1，因此跨 SQLite 版本不应要求 `.sqlite` 文件原始 SHA-256 相同。

本任务的“可重复构建”正式按以下门槛验收：

- JSON 字节级一致；
- 各逻辑表行数、主键集合和规范化内容 SHA-256 一致；
- SQLite `integrity_check`、`foreign_key_check` 通过；
- 构建记录 SQLite 库版本。

这不影响数据正确性，不构成返修理由。最终构建脚本和报告应避免把“跨环境 SQLite 文件逐字节一致”写成强制保证。
